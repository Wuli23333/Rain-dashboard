# 个人降雨可视化面板

一个单文件网页，用来看未来 72 小时的降雨预报，并重点回答一个问题：**这个预报有多确定。**

在线打开 → <https://wuli23333.github.io/Rain-dashboard/>

---

## 页面长什么样

页面从上到下分三层，第一眼只需要看第一层。

**第 1 层：一句结论。** 最上方一张横跨整行的大卡片，用一句话给出结论。这一层永远显示。

**第 2 层：6 张核心卡。** 固定 6 张，不多不少，一眼看完：

| 卡片 | 回答的问题 | 数字从哪来 |
| --- | --- | --- |
| 未来 24 小时降雨体感 | 下起来什么感觉 | 按**有效雨强**分档（小时雨强 × 风雨耦合系数，见下），主值直接给出档位名（如「中雨」）；副值给出有效雨强峰值与时刻，底部补一行 24 小时累计对应的国家标准等级，并保留原始雨强作对照 |
| 48 小时降雨概率 | 会不会下 | 50 个集合成员里，48 小时累计雨量超过 0.5 毫米的比例 |
| 未来 24 小时主要降雨时段 | 什么时候下 | 三个模型逐小时雨量的平均值里，雨量最大的一整段，给出起止时刻、该段累计、最强 1 小时雨强 |
| 气温与体感（24 小时） | 冷还是热 | 气温区间（三个模型平均）；体感温度直接取接口给的体感温度，给体感区间 |
| 模型一致性（未来 48 小时） | 三个模型同不同意 | 三个模型里有几个认为 48 小时累计雨量超过 0.5 毫米 |
| 48 小时雨量区间 | 最坏能到多少 | 集合成员的 P10 与 P90，覆盖中间 80% 的成员 |

**条件提示条（可选）。** 夹在第 1 层和第 2 层之间，只有出现危险或明显不舒服的天气时才显示，平时完全不占空间。命中条件时最多显示 3 条：能见度不足 2 公里、阵风超过 35 公里/小时、体感低于 5℃ 或高于 32℃、小时雨强超过 16 毫米/小时；同时命中超过 3 条时只挑最要紧的 3 条。

**第 3 层：详细数据。** 上面 6 张卡下面有一个「查看详细数据」的折叠条，点开才是其余全部内容（长时效指标、天气现象与降雨持续、不确定性明细、环境与体感、降雨构成、数据口径）。默认是收起的，展开状态记在浏览器本地，刷新后保持。

### 综合建议是怎么给的

| 判断依据 | 结论 |
| --- | --- |
| 三个模型都认为不下雨 | 都认为不下雨，不用带伞 |
| 三个模型都认为下雨，雨量分歧 < 20% | 雨会下，量也基本确定，按预报准备 |
| 三个模型都认为下雨，雨量分歧 ≥ 20% | 雨会下，但量不确定 → 带伞，别做防涝准备 |
| 只有一到两个模型认为下雨 | 模型对是否下雨都没共识 → 别信模型，去看雷达实况 |

卡片下方附一行小字说明依据，例如「依据：3/3 模型预测有雨；雨量相对分歧 70%；峰值时间跨度 5 小时」。如果有雨，还会追加一句**淋湿风险**（见下）。

### 风雨耦合与「有效雨强」

「降雨体感」卡不再只看原始雨强，而是把风一起算进去：**有效雨强 = 小时雨强 ×（1 + 风力系数）**。风力系数由平均风速与阵风按 0.6 : 0.4 加权合成，再分段线性映射成系数（0 公里/小时 → 0，10 → 0.2，20 → 0.5，30 → 1.0，超过 30 继续增大）。同一小时下 2 毫米的雨，无风和 25 公里/小时的风，体感档会从「小雨」升到「中雨」。卡片副值标注「已考虑风雨耦合」，底部保留「原始雨强峰值（未考虑风）」作对照。

> 这个系数是**经验近似，没有物理公式依据**，只为把「风会加重淋湿感」这个常识量化成可看的数字。

### 综合评分与「我的偏好」

「查看详细数据」折叠区顶部新增两组内容：

**分项分 + 综合体感分**：0 ~ 100 分，越高越不舒服。四项分别打分——降雨不适（0 毫米/小时 → 0 分，16 以上 → 100 分）、风力影响（0 公里/小时 → 0 分，40 以上 → 100 分，**有雨时权重 ×1.5**）、温度不适（20 ~ 26℃ → 0 分，0℃ 以下或 35℃ 以上 → 100 分）、能见度（10 公里以上 → 0 分，500 米以下 → 100 分），再按**降雨 40% ｜ 风 25% ｜ 温度 25% ｜ 能见度 10%** 加权成总分。每项和总分都有条形图，总分下方写明「⚠️ 权重为自定义设置，非国家标准，仅供参考」。

**我的偏好**：三个勾选框，勾选立即生效并保存在浏览器本地——「我有伞」把淋湿风险文案下调一档；「我会骑车 / 电动车」把风力权重 ×1.5，并在阵风超过 30 公里/小时时额外提醒侧风；「我怕冷」把温度权重 ×1.5。

### 淋湿风险

综合建议的副句里会追加一句淋湿风险，按有效雨强分四档：2.5 以下「有伞基本不会湿」、2.5 ~ 8「鞋会湿，建议防水鞋」、8 ~ 16「裤子也会湿」、16 以上「伞基本挡不住，尽量别出门」。勾了「我有伞」则整体下调一档。

### 一句统一的免责声明

所有涉及体感、评分、淋湿风险的卡片与提示条，底部都有同一句小字：**「体感与评分基于自定义映射规则与权重，非国家标准，因人而异，仅供参考。」**

### 关于「模型一致性」这张卡的一个说明

这张卡只统计 ECMWF、GFS、ICON 这三个确定性模型，而「48 小时降雨概率」和「48 小时雨量区间」来自集合预报接口，两者**不是同一个数据源**，结论可能相差很大。

例如 2026 年 9 月 23 日晚查兰州时，三个模型的 48 小时累计雨量是 0.20 / 0.00 / 0.00 毫米（都不足 0.5 毫米），而集合的 50 个成员里有 43 个超过 0.5 毫米，中位数 1.1 毫米。两个接口的时间窗口是对齐的，这是真实的模式差异，不是页面算错。但两张卡并排放在一起容易被读成自相矛盾，所以「模型一致性」卡上直接写明了这一点。

### 详细数据里都有什么

点开「查看详细数据」后，内容分成八组：

- **综合评分**：分项分（降雨 / 风 / 温度 / 能见度）＋ 综合体感总分，条形图展示（见上）。
- **我的偏好**：有伞 / 会骑车 / 怕冷 三个勾选框（见上）。
- **长时效（集合口径）**：未来 24 小时累计、未来 7 天累计（集合中位数）、未来 48 小时 P90、未来 7 天 P90。
- **天气现象与降雨持续**：官方天气现象、最长连续强降雨。
  - **官方天气现象**：按国际标准的 WMO 天气代码（雾、毛毛雨、雨、雪、雷暴等），取未来 24 小时内累计降水最多的那一小时对应的现象。因为天气代码是编号不是数值，取 ECMWF 一家，卡片上会注明。
  - **最长连续强降雨**：统计未来 24 小时内小时雨强达到 2.5 毫米/小时及以上的小时；如果分成了好几段，报最长那一段的起止时刻，并说明一共有几段。
- **不确定性明细**：降雨是否一致（48h）、雨量分歧程度、雨量区间（P10~P90）、峰值时间分歧。四张卡的算法见下。
- **环境与体感**：未来 24 小时气温、可用时段内最大风速、未来 24 小时云量、未来 24 小时最大阵风、未来 24 小时最低能见度。能见度还会按「通透 / 朦胧 / 有雾感 / 浓雾」分档。
- **降雨构成（雨 / 阵雨）**：逐模型列出雨与阵雨分别是多少。Open-Meteo 的 `precipitation = rain + showers`，但 ECMWF 不提供这个拆分（它的阵雨列恒为 0，降水量全部计入「雨」），卡片里写明了这一点，免得把 0 当成"没下阵雨"。
- **数据口径**：本次用了几个集合成员、几个模型可用。

**峰值时间分歧**一卡的判定细节：找出每个模型在 48 小时内雨下得最猛的那一小时，比较这几个时刻的早晚差距，按 ≤ 2 小时 / 3–5 小时 / > 5 小时分为一致、轻微分歧、明显分歧。判断「最猛」时要求那一小时至少下到 0.1 毫米/小时：48 小时拢共 0.6 毫米、每小时不到 0.02 毫米这种平缓细雨本来就没有峰值可比，卡片会直接写「无明确峰值」，不会随便挑一个小时报出来。如果只剩一个模型有明确峰值，则显示「样本不足」，并说明另外几个模型是因为雨强太小才没有参与比较。

**雨量分歧程度**一卡的口径：只在预报有雨的模型之间计算相对分歧 `（最大值 − 最小值）÷ 中位数`，并按 < 20% / 20–50% / 50–100% / > 100% 分为一致、轻微分歧、明显分歧、严重分歧四档，同时列出各模型的具体雨量。只有一个模型有雨时显示「样本不足，无法比较」。

### 数字显示到什么精度

预报本身没有到 0.01 毫米的把握，写出来就是编造精度。所以页面统一按下面的精度显示：

| 项目 | 显示方式 |
| --- | --- |
| 累计雨量（24h / 48h / 7 天） | 取整到 1 毫米；不足 1 毫米写「<1」，不写 0 |
| 集合分位数（P10 / P50 / P90） | 取整到 1 毫米，同上 |
| 概率 | 取整到 5%（3% 不会写成 0%，97% 不会写成 100%） |
| 模型间相对分歧 | 取整到 10% |
| 每小时雨强 | 保留 1 位小数（单位是毫米/小时） |
| 有效雨强（风雨耦合后） | 保留 1 位小数（单位是毫米/小时） |
| 综合评分（分项分与总分） | 取整到整数分 |
| 温度 | 保留 1 位小数，区间两端写法一致（如 `10.7℃ ~ 18.0℃`） |

缺数据一律显示「—」，不会用 0 顶替。0 是合法观测值，写成 0 会被读成"确实没下"。

### 降雨体感档和国标等级为什么不一样

「未来 24 小时降雨体感」卡里有两个不同口径的等级，故意分开写：

- **体感档**基于**有效雨强**（这一小时下得多猛，再叠加风力系数），从「无感」到「极端」共九档，是经验划分，回答"出门什么感觉"。
- **国标等级**基于 **24 小时累计量**（GB/T 28592-2012），回答"这是哪一档的雨"。

两者口径不同，所以同一场雨可能"体感是毛毛细雨、国标却是中雨"——累计不少、但每小时都很小。卡片底部写明了这一点。

## 图表

三张图都在「查看详细数据」里面。默认收起时不会绘制，展开后才画。

- **逐小时降雨总览**：柱状为逐小时降水量，折线为降水概率，双轴显示。
- **多模型对比**：ECMWF、GFS、ICON 三条曲线并排，可以看出三个模型从哪一刻开始出现分歧。
- **集合预报面条图**：50 条成员曲线叠加，粗线为中位数，用于观察预报分布的形状。

## 使用方法

### 1. 打开页面

浏览器访问 <https://wuli23333.github.io/Rain-dashboard/>。页面加载后会立即用当前坐标发起一次查询，不需要额外操作。

### 2. 设置位置

三种方式任选：

- **按地名搜索**：在「按地名搜索」中输入中文或拼音（如 `兰州` / `Lanzhou`），点「搜索」得到最多 5 条候选，点击其中一条即填入坐标并查询。
- **直接填坐标**：在「坐标输入」中填写纬度与经度，点「查询」。
- **用我当前位置**：点「用我当前位置」，由浏览器定位自动填入坐标。

默认坐标是甘肃兰州。填过的坐标会保存在浏览器本地，下次打开自动填入并自动查询。

> 「用我当前位置」需要 HTTPS 环境。本地双击 HTML 文件打开时该按钮会失效，改用另外两种方式即可。

### 3. 切换时间范围

图表上方的 24 / 48 / 72 小时按钮只影响图表的显示范围，不触发新的网络请求。结论与各张卡片始终基于未来 24 小时和 48 小时计算，不受切换影响。

### 4. 查看具体数值

鼠标悬停在任意图表上，会显示该时刻的完整数值；在集合面条图上还能看到对应的成员曲线。

### 5. 网络与坐标异常

- 坐标超出范围（纬度 −90 ~ 90，经度 −180 ~ 180）时，输入框会标红并阻止查询，问题在发请求之前就会被指出来。
- 请求失败时状态栏会说明失败原因（超时、接口报错、网络中断等），并提供重试按钮，重试使用输入框中的当前坐标。

页面用的是两个互不相干的接口，所以**一个挂了不会把整页带崩**。集合预报没取到时，页面照常显示模型对比、结论和图表，只在集合相关的位置降级：集合面条图整张收起、涉及集合的卡片显示「数据不可用」，页面顶部标注「1/2 个接口可用」并写明是哪个接口、什么原因。只有多模型预报这个主数据源失败时，页面才会显示失败原因并提供重试按钮。

### 6. 缓存

查询结果会在浏览器本地缓存 10 分钟，期间重复查询直接复用、不消耗接口额度。页面右上角显示当前缓存的条目数，旁边的「清空缓存」可手动清掉（没有可清的内容时按钮是灰的）。

因为可能复用的是几分钟前的数据，页面底部的时间标注的是**数据取回的时刻**，不是打开页面的时刻：

- 实时取回 → `数据时间：2026/9/23 18:43:07（刚刚）`
- 用了缓存 → `数据时间：2026/9/23 18:34:02（9 分钟前，其中 2/2 个接口来自本地缓存）`

两个接口的时间不一致时，显示**较早**的那个。

### 7. 在手机上使用

建议先用浏览器打开一次，再从浏览器菜单选择「添加到主屏幕」，之后即可像 App 一样启动。使用定位功能时浏览器会请求权限，选择「允许」即可。

## 数据从哪来

全部来自 [Open-Meteo](https://open-meteo.com) 的免费公开接口，不需要 API Key：

| 用途 | 接口 |
| --- | --- |
| 多模型预报（ECMWF / GFS / ICON） | `api.open-meteo.com/v1/forecast` |
| 集合预报（50 个成员） | `ensemble-api.open-meteo.com/v1/ensemble` |
| 地名转坐标 | `geocoding-api.open-meteo.com/v1/search` |

其中六个要素只有部分模型提供，页面按下面的规则处理：

| 要素 | 情况 | 页面怎么显示 |
| --- | --- | --- |
| 能见度 | 只有 GFS 有值，ECMWF / ICON 全是空值 | 显示 GFS 的值，并注明「仅 GFS 提供（1/3 个模型有值）」，不做跨模型平均 |
| 天气现象（天气代码） | 三个模型都有，但它是编号不是数值 | 取 ECMWF 一家、未来 24 小时里降水最多的那一小时对应的现象，并注明取自哪个模型 —— 两个编号求平均会得到没有意义的数 |
| 阵雨 | ECMWF 不提供雨 / 阵雨拆分 | 卡片里写明它的阵雨列恒为 0，不是"真的没下阵雨" |
| 体感温度 | 三个模型齐全 | 直接取接口给的体感温度（apparent_temperature），不自己套风寒 / 热指数公式；给 24 小时区间 |
| 阵风、雨量 | 三个模型齐全 | 三个模型求平均 / 取该时段峰值 |

页面本身是**一个 HTML 文件**，样式和脚本全在里面，没有构建、不用装任何东西。唯一的例外是画图用的 Chart.js 走 CDN——万一加载不上，图表位置会给出提示，其余功能照常。
