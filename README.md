# 降水快报

一个单文件网页应用，用于查询指定地点的降水预报，输出未来 48 小时降水的量级、概率与不确定性。

在线地址 → <https://wuli23333.github.io/Rain-dashboard/>

---

## 功能

页面自上而下分为三层。

**第一层：综合建议。** 顶部一张通栏卡片，用一句话给出结论（是否需要带伞），并注明把握程度与判断依据。

**第二层：3 张核心卡片。**

| 卡片 | 内容 | 数据口径 |
| --- | --- | --- |
| 什么时候下 | 未来 24 小时内雨量最大的一整段：起止时刻，以及这一段累计了多少毫米、这段里最强 1 小时多少毫米 | 三个模型逐小时平均 |
| 下多猛 | 按有效雨强（小时雨强叠加风力系数）分档，给出档位与峰值时刻；**下雪时**改按 24 小时降雪量报档位（微量降雪 / 小雪 / 中雪 / 大雪 / 暴雪 / 大暴雪 / 特大暴雪），并注明档位取自哪一家模型；**冻雨或冰雹时**改报这是什么天气（冻雨 / 有冰雹），数字改用 24 小时降水量累计并注明判据 | 下雨：三个模型逐小时雨强平均；下雪：24 小时降水累计（融水当量）；冻雨 / 冰雹：24 小时降水累计 |
| 穿什么出门 | 24 小时气温区间与体感温度区间，并据此给出穿什么；下雪且雪量够时补一句换防滑的鞋 | 三个模型平均；体感温度取接口直接给出值 |

**条件提示条。** 位于第一层与第二层之间，仅当出现危险或明显不适的天气时显示，最多 3 条，按优先级取前 3 条。触发条件包括：能见度不足 2 公里、阵风超过 35 公里/小时、体感温度低于 5℃ 或高于 32℃、有效雨强超过 16 毫米/小时。

**第三层：详细数据。** 3 张卡下方为「查看详细数据」折叠区，默认收起，展开状态保存在浏览器本地。内容依次为：

- 综合评分：先给一句口语档位（如「挺难受」），再指出影响最大的维度与其原始数值，分数与四条分项分（降水 / 风 / 温度 / 能见度）以降级的小字与条形图展示；
- 我的偏好：两个可选项（我会骑车 / 电动车、我怕冷），勾选即时生效并本地保存；
- 详细数据卡：长时效指标、天气现象与降水持续、不确定性明细、环境与体感、**积雪深度**、降水构成、数据口径；
- 三张图表：逐小时降水总览、多模型对比、集合预报成员曲线；
- 结论与建议。

### 综合建议的判定

| 条件 | 结论 |
| --- | --- |
| 三个模型均认为不下雨 | 都认为不下雨，不用带伞 |
| 三个模型均认为下雨，雨量分歧 < 20% | 建议带伞，量级基本确定 |
| 三个模型均认为下雨，雨量分歧 ≥ 20% | 建议带伞，但雨量不确定 |
| 仅有部分模型认为下雨 | 建议带伞，但模型意见不一，临近看雷达 |

判定顺序为：先看三个模型是否认为有雨（雨量共识），再看 24 小时概率峰值与累计雨量。带伞动作与把握程度三处（综合建议卡、条件提示条、折叠区结论）引用同一份判定，口径一致。

**冻雨与冰雹是另一类结论。** 这两种天气不是"要不要带伞"的问题：冻雨落地就结冰、冰雹要躲开，所以它们有各自的动作（冻雨「有冻雨，落地就结冰，尽量别出门」、冰雹「有冰雹，找地方躲，别在外面停留」），结论横幅也随之变成「找遮蔽处，别在外面停留」，不会出现「基本不用带伞」。同一份判定还管着阵风提示条：冻雨或冰雹天里，那条提示只会提醒尽快进到遮蔽处，不会再对着伞说话。

### 综合评分与偏好

评分卡顶部先说一句人话，再说分数：**主值**是一个口语档位（0–19 舒服的一天 / 20–39 还行 / 40–59 有点将就 / 60–79 挺难受 / 80–100 能不出门就别出门），**副标题**指出四个维度里影响最大的那一项，并带上它的原始数值与单位（例如「主要是风：阵风 40 km/h，骑车会明显吃力」），**分数则降级成一行小字**（形如「综合 51 分」），与四条分项条形图一起作为内部刻度保留。

评分权重为降雨 40%、风 25%、温度 25%、能见度 10%，有雨时风力权重上调；勾选偏好后权重随之变化，副标题里的「最大那一项」也会跟着变。分项分与总分按分数分档着色（40 分以下绿、40–69 黄、70 以上红）。评分与偏好的权重均为自定义设置，非国家标准；统一免责声明全页只出现一次（在页脚）。

### 数字精度

| 项目 | 显示方式 |
| --- | --- |
| 累计降水量、集合分位数 | 取整到 1 毫米，不足 1 毫米写「<1」 |
| 概率 | 取整到 5% |
| 模型间相对分歧 | 取整到 10% |
| 每小时降水强度、有效降水强度 | 保留 1 位小数（毫米/小时） |
| 降雪量（会积多厚） | 用厘米（1 厘米步长），并注明是哪一家模型的读数 |
| 积雪深度 | 不足 1 米用厘米（1 厘米步长）、1 米以上用米（0.1 米步长） |
| 综合评分 | 取整到整数分 |
| 温度 | 保留 1 位小数 |

页脚会并排列出三个「水」的单位：**降水量 = 毫米（mm）**、**降雪量 = 厘米（cm）**、
**积雪深度 = 厘米（cm）/ 米（m）** —— 它们是三个不同的量，不要互相换算着看。

缺失数据一律显示「—」，不用 0 顶替。

## 使用方式

### 1. 打开页面

浏览器访问 <https://wuli23333.github.io/Rain-dashboard/>，页面加载后自动确定地点并查询一次。

地点的确定顺序（前一步成功就不再走下一步）：

1. 使用上次保存的坐标（保存在浏览器本地）；
2. 否则**先用默认坐标（甘肃兰州 36.10, 103.77）把数据查出来**，同时在后台尝试浏览器定位（最长等 3 秒）；
3. 后台定位成功 → 自动改用你的位置再查一次（地点标签随之变成「当前位置 · …」）；
4. 定位被拒绝、超时或浏览器不支持 → 保持第 2 步的结果，不做任何事。

这样第一次打开时**不会为了等定位而空着页面**：数据先出来，位置后补上。

定位结果只用于查询，不写入本地保存的坐标；用户自己发起查询后，尚未返回的定位结果会被放弃。

### 2. 设置位置

页面上方有一张「输入地点 / 坐标」卡，默认收起成一行。点开后可任选三种方式：

- 按地名搜索：输入中文或拼音（如 `兰州` / `Lanzhou`），点击候选结果填入坐标并查询。
  每条候选都带一个级别标签（首都 / 省会 / 地区中心 / 县驻地 / 村镇 …）。
  ⚠ 地名库**只收录城市与村庄，不收录省 / 州这类行政区** —— 搜「山东」搜不到山东省，
  返回的是各地同名的村庄（这种情况页面会在列表上方给出重名提示，说明它们在哪些省份）。
- 直接填坐标：填写纬度与经度后查询；
- 用当前位置：由浏览器定位填入坐标。

查询成功后该卡自动收起；失败则保持展开以便修改。查询成功的坐标与地名保存在浏览器本地，下次打开自动填入。

收起状态下，该行右侧显示当前查询所用的地点：搜索选中的地点显示地名（如「西安，陕西」），定位得来的显示「当前位置 · 39.90, 116.41」，默认坐标显示「默认地点 · 36.10, 103.77」。

> 定位功能需要 HTTPS 环境：在线地址（GitHub Pages）可用；**以文件方式双击打开时浏览器会禁止定位**，
> 此时页面不去尝试定位，直接用默认坐标出数据（不等、不报错）。

### 3. 切换时间范围

核心卡下方的 24 / 48 / 72 小时按钮只影响三张图表的显示范围，不触发新的网络请求。结论与卡片始终基于未来 24 小时与 48 小时计算。

### 4. 查看数值

鼠标悬停在图表上可查看该时刻的具体数值。

### 5. 异常处理

- 坐标越界（纬度 −90 ~ 90、经度 −180 ~ 180）会在请求前标红并阻止查询；
- 请求失败时状态栏说明原因并提供重试按钮。

页面同时使用两个相互独立的数据接口（多模型预报与集合预报），任一接口失败不会影响页面整体。集合预报不可用时，仅集合相关卡片降级为「数据不可用」；仅当多模型预报（主数据源）失败时，页面才整体报错并提供重试。

### 6. 缓存

查询结果在浏览器本地缓存 10 分钟，期间重复查询复用缓存。页面页首显示缓存条目数，可手动清空。页脚时间标注的是数据取回时刻（非页面打开时刻），使用缓存时会注明。

### 7. 移动端

浏览器打开后可通过「添加到主屏幕」作为应用使用。

## 数据来源

数据全部来自 [Open-Meteo](https://open-meteo.com) 的公开接口，无需 API Key。

| 用途 | 接口 |
| --- | --- |
| 多模型预报（ECMWF / GFS / ICON） | `api.open-meteo.com/v1/forecast` |
| 集合预报（50 个成员） | `ensemble-api.open-meteo.com/v1/ensemble` |
| 地名转坐标 | `geocoding-api.open-meteo.com/v1/search` |

部分要素只有部分模型提供，页面按以下规则处理：

| 要素 | 情况 | 处理方式 |
| --- | --- | --- |
| 能见度 | 仅 GFS 有值 | 显示 GFS 值并注明来源，不做跨模型平均 |
| 天气现象（WMO 天气代码） | 三模型均有，但为编号非数值 | 取 ECMWF 单模型，取 24 小时内降水最多的那一小时对应现象 |
| 降雨 / 降雪 / 积雪深度 | 三个模型都提供，但常各不相同 | 降雨取平均；**降雪与积雪深度不跨模型平均**，取"报得最多的那一家"并注明是哪一家；积雪深度还会剔除"整段不变"的可疑读数（详见下） |
| 阵雨 | ECMWF 不提供雨 / 阵雨拆分 | 注明其阵雨列恒为 0 |
| 体感温度 | 三模型齐全 | 直接取接口值，不另套公式 |
| 阵风、雨量 | 三模型齐全 | 三模型平均或取峰值 |

### 风力怎么看

页面给的是**蒲福风级**（我国标准 GB/T 28591—2012《风力等级》），主值形如「5 级 劲风（29~38 公里/小时）」，
下面一行是该风级在**陆地上的现象**（标准原文，例如 5 级是「有叶的小树摇摆，内陆的水面有小波」）。

三点请特别注意：

- **风级配的是"平均风"**（10 米高度处的风速），不是阵风 —— 这是标准本身的口径。
  所以卡片标题写的是「风力（陆上 10 m）」；
- **阵风单列一张卡**，只报数值 + 阵风自己的档名（如「风大，注意帽子与骑行安全」），
  不给蒲福的陆地现象。原因：阵风 40 公里/小时的等效平均风只有 4 级左右，
  拿阵风去套 5 级、6 级的现象描述就是张冠李戴；
- 综合评分里的「风力影响」分项分**用的是同一个数**（平均风峰值），
  分数越高对应的风级越高、卡片上的现象描述也越"重" —— 三处不会互相打架。

完整的风级表（1~9 级，含 m/s 与公里/小时区间）由页面自己按标准实现；
现象描述逐字抄自标准的**附录 A**（资料性附录，不是标准正文条款）。
标准原文可在[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=BD0C47493F5ABA08B24176BF8A81218A)查询（原文 PDF 已取得并核对，表体摘录见工作区 `standards/README.md`）。

### 降雪量级怎么分级

判据是**未来 24 小时的降水量**（融水当量，毫米），分七档：

| 档位 | 24 小时降雪量 |
| --- | --- |
| 微量降雪（零星小雪） | 大于 0、小于 0.1 毫米 |
| 小雪 | 0.1 ~ 2.4 毫米 |
| 中雪 | 2.5 ~ 4.9 毫米 |
| 大雪 | 5.0 ~ 9.9 毫米 |
| 暴雪 | 10.0 ~ 19.9 毫米 |
| 大暴雪 | 20.0 ~ 29.9 毫米 |
| 特大暴雪 | 30.0 毫米及以上 |

分级依据 GB/T 28592-2012《降水量等级》**表 2 的 24 小时一列**（原文 PDF 已核对，逐档一致）。**完全没下雪**（累计为 0）不进任何档，与"下了 0.05 毫米"分开；数据缺失时显示「—」，不用 0 顶替。
页面同时说明档位取自哪一家模型（如「降雪档位按「ICON」的读数（3/3 个模型有值）」），某一家没有数据时不计入，也不会被当成"这一家报了 0"。
⚠ 官方口径里的"降雪量"只算固态降雪、不含雨夹雪；本页判据用的是接口给的降水量（含雨），
所以**雨雪混合**的天气下档位可能偏大一格 —— 这种情况页面会直接写出来。
（标准本身把"降水量"定义为"液态或固态降水**经融化后**积聚的深度"，所以用降水量当判据是同一量纲。）

档位数值的出处：[国家标准全文公开系统 · GB/T 28592-2012](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=B4A00E4ABCF80F8C6A048C1D0121A97D)（原文 PDF 已取得并逐条核对；工作区留了表体摘录 `standards/README.md`）、
以及[中国气象局·暴雪认定条件](https://www.cma.gov.cn/wmhd/gzly/20CMAckly/202308/t20230822_5727276.html)（暴雪三档，与表 2 逐值一致）。

### 积雪深度怎么看

「积雪深度」说的是**地上已经积着的雪**（含常年积雪），不是今天新下的 —— 页面会明确写出来。
它**只报数值、不做分级**：目前没有可核的依据能说明"多厚就走不了路"（查到的只有灾害分级标准，
不是通行性判断），所以页面不替这个数下结论。

三个模型对同一个点的积雪深度**可能差很多**（实测格陵兰冰盖上一个点：1.46 米 / 20.35 米 / 40 米）。
其中有的模型会返回"整段 48 小时一动不动"的数值 —— 那不是预报结果，而是填充值，
页面会把它**排除在主值之外**，但仍然在卡片小字里**把三家的原始读数并列出来**并标注哪个被剔除。
所以：主值旁边一定能看到三家各自的数，遇到分歧大的地方请以"分歧极大"这句提示为准。

## 技术说明

页面为单个 HTML 文件，样式与脚本内联，**图表库 Chart.js（v4.4.1）也已内联**，无构建步骤、无依赖安装。
因此双击打开（不联网）时图表同样能正常显示 —— 不依赖任何 CDN。
